# History — phase-2-database-and-ingestion

**Status:** in progress (Supabase project pending) · **Started:** 2026-10-24

## Done
- `docker-compose.yml`: local Postgres 16 on port 5433 (dev and DB tests only; production is Supabase).
- `backend/app/db/models.py`: customers, events, user_profiles, saved_reports, predictions (timestamptz, JSONB, FKs, CHECK on `risk_score`, indexes `(customer_id, event_timestamp)` and `(event_name, event_timestamp)`).
- `backend/app/db/session.py`: engine/session dependency from `DATABASE_URL`.
- Alembic wired to `DATABASE_URL`; initial migration `0001_initial_schema` autogenerated.
- `backend/app/schemas/events.py`: Pydantic event contract (allow-listed names, id pattern/length, tz-aware timestamp normalised to UTC, flat scalar properties capped at 4 KB, unknown fields forbidden).
- `backend/app/services/ingestion.py`: per-row validation, rejected rows reported by index and reason (values never echoed), customers resolved/created, `INSERT ... ON CONFLICT (event_id) DO NOTHING`, one transaction (rollback on failure), batch cap 5,000.
- `backend/scripts/load_events.py`: loads the synthetic `events.csv` through the service.
- Tests (`tests/test_ingestion.py`, `conftest.py`): valid insert, re-ingest, in-batch and overlapping duplicates, 4 concurrent writers, malformed payloads, no payload echo, UTC normalisation, rollback. Tests run the real migration on a clean schema and skip if Postgres is unreachable.

## Decisions
- Idempotency is enforced by the UNIQUE constraint plus `ON CONFLICT DO NOTHING`, not check-then-insert.
- Customers unknown to the table are auto-created with `created_at` = earliest event in the batch (placeholder; `plan` from `customers.csv` is not loaded yet).
- Event-name allow-list is enforced in the application, not by a DB CHECK, so adding a name needs no migration.
