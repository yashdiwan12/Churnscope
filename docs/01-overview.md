# 1. Overview

> **Status legend** used across all docs: `[Planned]` designed, not built · `[In progress]` · `[Built]` implemented and tested.
> Phases 0-3 are `[Built]` (setup, data and metric definitions, database and ingestion, analytics API). Everything else is `[Planned]`. Update tags as phases complete (see [History](10-project-history.md)).

## What Churnscope is

A portfolio-grade product analytics platform that turns user-activity events into **engagement, funnel, retention, and churn-risk** insights.

It answers four questions for a SaaS team:

1. Are users actively using the product?
2. Where do users drop out of important workflows?
3. Which cohorts return over time?
4. Which customers show behaviour associated with future churn?

## Guiding principle

Deliver a small, correct, end-to-end MVP before adding sophistication. **Never claim scale, accuracy, or performance that has not been measured.** No model-performance target is assumed; actual evaluation results are reported.

## MVP definition of done

- A developer can set the project up from documented instructions.
- Users sign in with Google via Supabase Auth.
- A documented dataset loads; validated events are ingested idempotently.
- Engagement, funnel, and retention metrics are correct on hand-checked examples.
- A churn model trains and evaluates reproducibly.
- Streamlit shows analytics and model output.
- Private saved data is accessible only to its owner.
- Tests cover ingestion, analytics, authorization, and ML.

## Scope

| Tier | Items |
|---|---|
| **P0 (MVP)** | Modular Python app · dataset notes + validation · Supabase PostgreSQL + SQLAlchemy · Google OAuth · token verification + server-side authorization · idempotent ingestion · overview/funnel/retention analytics · leakage-aware baseline churn model · Streamlit + Plotly dashboard · tests, README, architecture diagram |
| **P1 (after MVP)** | Saved reports/watchlists · segmentation · model explanations + threshold comparison · richer cohort/feature-adoption views · scheduled refresh/retraining · Docker + deploy automation · monitoring |
| **Out of scope (v1)** | Kafka/streaming · microservices · large-scale infra · LLM chatbot · billing · production-scale real-time claims · heavy orchestration |

## Technology stack

| Component | Technology | Responsibility |
|---|---|---|
| Language | Python | App, analytics, ML |
| Data | Pandas, NumPy | Validation, aggregation, features |
| ML | scikit-learn | Baselines, classification, evaluation |
| Backend | FastAPI + Pydantic | REST API, validation |
| Auth | Supabase Auth + Google OAuth | Sign-in, identity |
| Database | Supabase PostgreSQL + SQLAlchemy | Customers, events, predictions |
| Frontend | Streamlit + Plotly | UI and charts |
| Testing | pytest, FastAPI TestClient | Unit + integration |

**Supporting choices (decided 2026-10-23):**

| Area | Choice |
|---|---|
| Python | 3.12 |
| Packaging | `uv` + `pyproject.toml` + lockfile; separate `backend/` and `frontend/` projects |
| DB driver | `psycopg` 3 with SQLAlchemy 2.x |
| Migrations | Alembic (introduced in Phase 2) |
| JWT verification | PyJWT against Supabase JWKS |
| HTTP client | `httpx` (frontend → API) |
| Dataframes | Pandas (not Polars) |
| Metric computation | SQL aggregation in Postgres, Pandas post-processing |
| Model serialization | `joblib` |
| Lint/format | Ruff |
| CI | GitHub Actions with Postgres service container |
| API host | Render |

Not used: `yfinance`, `pandas-ta` (finance-specific).

## Data approach (decided)

Two **clearly separated and labelled** data sources:

- **Synthetic event log** — timestamped events generated by a documented script; powers funnels, retention, engagement, and time-based churn features.
- **Public churn dataset** — a static snapshot used for a supplementary classifier; it has no real timestamps, so no temporal-validation claims are made for it.

Details in [Data model](05-data-model.md).
