# Data dictionary

## Synthetic event log (**synthetic, seeded**)

Generated by `backend/scripts/generate_events.py` (`--seed 42`, 2,000 customers, 180 days from 2026-01-01 by default; output in git-ignored `data/processed/`). Shapes of funnels and retention come from the generator's assumptions, not from real behaviour.

### `customers.csv`
| Column | Type | Notes |
|---|---|---|
| external_customer_id | string | `c00000`... unique |
| created_at | timestamp UTC | signup time |
| plan | string | `free` (60%), `pro` (30%), `team` (10%) |

### `events.csv`
| Column | Type | Notes |
|---|---|---|
| event_id | string | unique, `e00000001`... (idempotency key) |
| customer_id | string | references `external_customer_id` |
| event_name | string | one of the allow-list in [metrics](metrics.md) |
| event_timestamp | timestamp UTC | events at or after the end of the generated period are dropped |
| properties | JSON string | `{"feature": ...}` for `feature_used`, else `{}` |

Generator assumptions: ~75% of customers complete onboarding; ~55% of those flagged create a report; each customer has a geometric "churn week" after which they stop; weekly activity is Poisson with a per-customer gamma-distributed rate.

Validation done: `event_id` unique, names within the allow-list, timestamps tz-aware UTC and within the period (`tests/test_generate_events.py`).
