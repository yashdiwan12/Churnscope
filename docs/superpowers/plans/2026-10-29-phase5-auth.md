# Phase 5 Authentication and Authorization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Only allow-listed Google users reach analytics, churn and `/me*`; event producers write through `POST /events` with a service key; one user can never read or delete another user's reports.

**Architecture:** FastAPI verifies Supabase-issued JWTs itself (`core/security.py`, network-free apart from an injectable JWKS client), then checks an env allow-list (`core/authorization.py`). Ownership lives in `db/reports.py`, the only module that queries `saved_reports`. Streamlit signs in through Supabase with PKCE and sends the access token as a Bearer header.

**Tech Stack:** FastAPI, PyJWT + cryptography (already dependencies), SQLAlchemy, pytest; Streamlit + httpx on the frontend.

**Spec:** `docs/superpowers/specs/2026-10-29-phase5-auth-design.md` (the executor reads both; section numbers below refer to it).

## Global Constraints

- Token checks (spec 5.1): `exp`, `sub` valid UUID, `aud == "authenticated"`, `iss == {SUPABASE_URL}/auth/v1`, `role == "authenticated"`, `is_anonymous` not true; leeway 10 s; algorithms ES256/RS256 via JWKS, HS256 only if `SUPABASE_JWT_SECRET` is set; everything else (including `none`) rejected.
- Failure bodies: 401 `{"detail": "Not authenticated"}` + `WWW-Authenticate: Bearer`; 403 `{"detail": "Not allowed"}`; 503 `{"detail": "Authentication unavailable"}`; ingest unset key 503 `{"detail": "Ingestion is not configured"}`. Fail closed always.
- Empty allow-list allows nobody; emails compared lower-cased, exact; domains exact after `@`.
- Identity only from the verified token; request schemas use `extra="forbid"`.
- Never log or return tokens, claims payloads or the ingest key; logs carry the user id only.
- Ownership miss is **404**, never 403. Max 100 reports per user (101st is 409). `filters` JSON capped at 4 KB. `report_type` in `overview|funnel|retention|engagement|churn`.
- `POST /events`: `X-API-Key`, `hmac.compare_digest` over SHA-256 digests; body > 5 MB is 413; > 5,000 events is 422. `X-API-Key` is not a CORS-allowed header.
- No test calls Supabase. Tests never run against the Supabase project (`TEST_DATABASE_URL` only). Never print or commit `.env` or any key.
- Code style: ruff, line length 100; `uv run` from `backend/`. Commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

Each line is pinned by a test in the task named in brackets.

1. `Authorization` header oddities: `bearer` lower-case works, `Basic x`, `Bearer` with no token, two tokens → all 401, never 500 [Task 2].
2. A token whose `email` claim is not a string (list, number) → 403, not a crash [Task 2].
3. JWKS has no key for the token's `kid` (key rotation) → 401, while the JWKS endpoint being unreachable → 503 [Task 1].
4. `limit`/`offset` out of range on `/me/reports` (0, 101, -1) → 422; non-integer report id on DELETE → 422 [Task 3].
5. `X-API-Key` present but empty, or an `events` body with an unknown top-level field → 401 / 422 [Task 4].
